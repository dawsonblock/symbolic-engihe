# SIS v3 bounded symbolic learning upgrade — 2026-10-24

This is an upgraded **research implementation**, not a demonstrated autonomous
self-improving coding agent. Existing package metadata is kept at v2.4.0 to
avoid claiming a qualifying v4.0 release.

## Included changes

- `sis.v3.learning.strategies`: deterministic, contrastive extraction of common
  diagnostic actions from receipt-verified cross-repository episodes.
- `sis.v3.learning.symbolic`: candidate-only AST single-operator mutation
  detection; never auto-applies transformations or claims semantic correctness.
- `sis.v3.learning.optimization`: bounded candidate selection based on paired,
  independently verified transfer trials with repository identity supplied by
  task registration (not code-tree hashes).
- `sis.v3.learning.records`: converts extracted knowledge into typed V1
  **candidate-only** procedures for subsequent independent qualification.
- `sis.v3.authority` and `sis.v3.secure_guidance`: verified decision-backed
  guidance projection and strict repository isolation. No verified promotion
  decision means no servable qualified procedure.
- `sis.v3.nonce_store`: persistent SQLite nonce admission for one-time signed
  evaluation envelopes. Plain `verify_envelope` remains a read-only verifier.
- `sis.v3.benchmark`: budget-invalid passes excluded from solves/paired wins;
  exact monotonic elapsed-time gate before canonical integer reporting; optional
  token/tool usage counter checks. **Agent runtime must still enforce hard
  deadlines and supply trustworthy token/tool counters.**
- `tools/build_canonical_zip.py`: deterministic archive build with one manifest,
  final ZIP verification, and strict tree-mode symlink detection.

## Hard security limitation

Legacy `ProcedureStore.add(... allow_qualified=True)` and legacy
`GuidanceGateway` are retained for compatibility. They are **not secure
production-serving entry points**. For production admission and retrieval, use
`StrictGuidanceGateway` constructed with an independently configured
`PromotionController`, and bind repository ownership through trusted task
registration. Never give agents direct store or decision-ledger write access.

The old promotion implementation appends catalog revisions before decisions.
The strict gateway fails closed on a torn promotion, but automatic replay or
rollback after a crash is not implemented here. These are independent release
blockers; storage separation and evaluator custody are required before hostile
code is permitted. `min_distinct_repos` in older promotion code still counts
repository *tree digests* and is not sufficient proof of repository disjointness.

## What has *not* been demonstrated

- An authenticated Codex SDK live run, isolation and event streaming under a
  production workload.
- Generalized code-transformation correctness beyond one source AST change.
- Autonomous skill optimization with controlled signed receipts and sealed
  independently graded evaluation data.
- Real measured improvement on untouched repositories.
- Production-proof atomic qualification transaction and hardened OS sandbox.

The imported designs are informed by ReasoningBank and EvoSkill, but their
source code has not been blindly merged or bundled. `vskill` has not been
combined; it is an optional packaging/scanning dependency at most.
