# v1.8 — Frozen skill closures, one-use sealed evaluation, and pseudo-label export

## Precisely what this adds

- `sis.skill_bundle` freezes a **specific active procedural skill** plus all needed active same-namespace dependencies, with exact AST, schema, local train/validation evidence digests, and checked catalog audit head. The hash **detects modifications**, but is **not** a signature or independent proof that the source DB was honest.
- `sis.skill_holdout` provides **evaluator-owned** SQLite custody of two private label sets (`holdout` and `shifted_holdout`), a precommitted policy and frozen candidate hash, HMAC-authenticated public manifests and aggregate score receipts, and **at-most-one successful scoring** per evaluation. Every scoring result can be replayed by the evaluator; no holdout inputs or labels appear in the public manifest, score receipt or verification output.
- `sis.distillation` emits chat-style JSONL **pseudo-labels generated by a qualifying frozen skill** on new caller-provided inputs. Custodian-side duplicate, schema, and private holdout/exclusion overlap checks are required. The manifest carries an HMAC-bound SHA-256 of the output JSONL. It **does not train, fine-tune, or modify an LLM**.
- All core v1.0–v1.7 workflows remain present; the v1.4 evaluator is unchanged and evaluates traditional SIS rules, not procedural skills. v1.8's separate evaluator handles procedural skill ASTs.

## Trust model (read before using)

The *candidate author* controls model prompts, training examples and learning/promotion; the *evaluator custodian* must separately control the private holdout labels, vault database, 32+-byte HMAC secret and policy. An archive with demo synthetic examples does **not** demonstrate independent evaluation. Do not expose `skill-eval-seal`, `skill-eval-score`, `skill-eval-recover`, or `skill-distill-export` to untrusted agent tool calls or a public HTTP endpoint.

The public manifest contains a **hash of the private dataset**, not the dataset itself. This does not conceal a small or guessable dataset against offline enumeration; keep the entire vault and the private source data confidential. Evaluation does not prove that the label origin is independent. The `excluded_inputs` field catches exact overlaps only for inputs the custodian explicitly supplies; it is **not a complete data provenance guarantee**. A precommitted `policy_pass` is not a publication-grade generalization result, and it does not imply a live registry skill is currently active.

HMAC receipts demonstrate integrity **only relative to the evaluator's separately protected key**. If a single operator controls the candidate, key and private labels, the resulting receipt is internal evidence. SQLite file backups, secrets custody, and evaluator process isolation are operational responsibilities. These procedures do not provide hardened OS isolation against adversarial code running with the evaluator's privileges.


The demonstration intentionally creates fake list-sum holdouts in memory and uses one process for both sides; treat its scores as software tests only.

## Real custodian workflow

First, on the **producer** host, perform approved v1.7 learning from trustworthy labeled training/validation records. Use the returned `promotion.id` to freeze the active skill and full dependency closure:

```bash
sis --db ./producer.sqlite skill-study examples/skill_sum_study.json
sis --db ./producer.sqlite skill-freeze <PROMOTION_SKILL_ID> frozen-bundle.json --namespace list_sum
```

Transfer only the frozen bundle to the **evaluator-controlled** environment. The private evaluator JSON is strictly:

```json
{
  "study_id": "sum_study_01",
  "task_description": "Return the sum of the integers in nums.",
  "holdout": [ {"inputs": {"nums": [10,20,30]}, "output": 60} ],
  "shifted_holdout": [ {"inputs": {"nums": [-10,20,30]}, "output": 40} ],
  "excluded_inputs": [ {"nums": [1,2,3]} ],
  "policy": {
    "min_per_split": 30,
    "min_coverage": 0.95,
    "min_overall_accuracy": 0.90,
    "min_wilson_lower": 0.80
  }
}
```

That snippet is **schema illustration only**; an actual evaluation requires at least `min_per_split` (30 here) **unique, disjoint** examples in *each* split, with the same schema as the frozen skill. For reproducibility use a locked dataset and custodian signature; do not edit labels after sealing. Also pass all known original training/validation inputs in `excluded_inputs` so exact duplicates are rejected.

`task_description` is optional for compatibility with existing v1 datasets. When omitted, SIS uses a generic instruction to apply the frozen skill's demonstrated transformation; new evaluations should provide a specific description so model prompts and distillation exports state the task clearly.

```bash
# Set SIS_EVAL_HMAC_KEY in the evaluator's secret environment before running.
sis skill-eval-seal custodian-private.json frozen-bundle.json public.json --vault ./private/evaluator.sqlite
sis skill-eval-score public.json frozen-bundle.json receipt.json --vault ./private/evaluator.sqlite
sis skill-eval-verify public.json frozen-bundle.json receipt.json --vault ./private/evaluator.sqlite
# If a scoring transaction committed but writing receipt.json failed:
sis skill-eval-recover public.json frozen-bundle.json recovered-receipt.json --vault ./private/evaluator.sqlite
```

A private dataset is **never** sent as input to `skill-eval-score`; that command reads private labels only from the evaluator's vault. Scoring happens once and produces aggregate counts, coverage, overall accuracy, and 95% Wilson lower confidence bounds **separately** for both groups. A policy failure is reported as such; no knowledge registry is modified or promoted as a result.

## Pseudo-label export for later neural training

After a `policy_pass`, the evaluator can export training candidates selected **without consulting secret holdout labels**. `fresh-inputs.json` is a JSON list of new, unique, schema-correct input objects.

```bash
sis skill-distill-export public.json frozen-bundle.json receipt.json fresh-inputs.json training.jsonl --vault ./private/evaluator.sqlite
```

This produces `training.jsonl` (chat message rows) and `training.jsonl.manifest.json` (HMAC-signed provenance and SHA-256). It refuses exact overlap with every input in the vault's test, shifted test, and supplied excluded-input sets. This step is intentionally evaluator-custodian-only, because a public overlap oracle can itself expose membership information.

**Do not confuse pseudo-labels with ground truth.** They reflect the program's predictions, including its undiscovered failures; they are not a safe replacement for independently labeled data. To distill into a local 3B–8B model, subsequently build a separate training pipeline with explicit human approval, weight/data versioning, leakage checks and fresh task-family validation. Nothing in v1.8 performs that training.

## Failure and attack cases covered by tests

- Mutated bundle and HMAC receipt; public policy/manifest tampering; wrong HMAC key
- Incomplete and duplicate dependency closures; schema and output type enforcement
- Reused evaluation attempts, cross-connection and concurrent one-use enforcement
- Private vault-data alteration, replay failures, policy fail and export rejection
- Duplicate inputs, overlap across both holdouts and declared exclusion records
- Fully automated offline CLI workflow, receipt recovery, and signed export manifest

## Quantitative limitations

The two test sets must contain 10–256 cases each, according to the precommitted policy. More examples are often needed for meaningful lower bounds. The Wilson interval is descriptive under a binomial sampling assumption and does **not** correct for correlated, nonrandom or adversarial datasets. The policy is not a guarantee of causal transfer to new task families; add independent family-level splits, retrieval-only and prompt-matched baselines, and real-LLM cost/accuracy experiments before claiming improved intelligence.
